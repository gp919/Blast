# AI 협업 로그

AI 도구를 개발에 활용하면서, **출력이 틀렸던 것과 그것을 어떻게 찾아 고쳤는지** 기록합니다.

"AI로 빠르게 만들었다"는 누구나 하는 말이라 어필이 약합니다.
**출력의 오류를 기술 이해로 잡아냈다**는 사례가 AI 친숙도와 기초 실력을 동시에 증명합니다.
자소서와 면접에서 쓸 근거를 여기에 모읍니다.

## 기록 기준

- 대상: 설계 판단 오류, 네트코드 로직 오류, 결정성 위반, 성능 함정
- 제외: 오타, 단순 컴파일 에러, API 이름 착오

## 작성 형식

```
### YYYY-MM-DD | 제목

- 맥락: 무엇을 만들고 있었나
- AI 출력: 무엇을 제안했나
- 문제: 왜 틀렸나 (원리 수준으로)
- 발견 경위: 어떻게 알아챘나
- 수정: 어떻게 고쳤나
```

**"발견 경위"를 반드시 쓰세요.** 면접에서 실제로 파고드는 건 이 부분입니다.

---

## 기록

### 예시 (첫 항목 작성 후 삭제)

**2026-08-15 | 재조정 되감기 시작 틱 오프셋 오류**

- 맥락: 서버 상태 수신 후 불일치 시 재시뮬레이션하는 로직 구현 중
- AI 출력: 수신한 서버 틱 번호부터 재시뮬레이션 시작
- 문제: 서버 스냅샷은 해당 틱 처리가 **끝난 뒤**의 상태이므로, 그 틱부터 다시 돌리면
  입력이 한 번 중복 적용됨. `serverTick + 1`부터 시작해야 함
- 발견 경위: RTT 150ms에서 계속 이동하면 캐릭터가 조금씩 앞서 나가는 현상.
  디버그 오버레이로 서버 위치와 예측 위치를 겹쳐 그려 편차가 누적되는 것을 확인
- 수정: 재시뮬레이션 시작 인덱스를 +1로 보정하고, 입력 버퍼에서 해당 구간만 재적용
